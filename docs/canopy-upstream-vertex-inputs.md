NVN vertex fetch supplies integer register bits for pure integer bound formats and float bits for other supported formats. Metal fixes an input's type in its function declaration. The port redeclares mismatched vertex inputs for the bound format and uses `as_type` at their reads to preserve the original shader's register interpretation. Normalized and floating formats remain in the float class; NVN's explicit integer-to-float conversion formats `0x51..0x68` also use that class. Unknown or unbound formats retain the existing descriptor behavior. Unbound inputs keep their declared type and existing constant-input fallback.

Both runtime and seed preparation stop requiring equality of recorded vertex-input type dependencies. Texture, image and fragment-output dependencies retain their existing comparisons. The renderer must therefore refuse a candidate when it needs a retype but has no readable MSL. Unlike upstream's log-and-drop fallback, this port returns nil and marks the existing missing-variant state. The source is captured before scheduling a derived function. A missing declaration or required output structure similarly produces a cached `VARIANT_NONE` refusal instead of an original-function fallback or a new fatal declaration diagnostic. The sentinel is translated to nil at both cache lookup and concurrent publication return; it cannot become a Metal vertex function. Existing non-retyping failure policies remain unchanged. This does not claim a general MSL validator.

The existing reflection converter bounds vertex input count and locations by `NVN_REFL_MAXV` (32) before filling the fixed reflection array. Its `nvn` and `loc` fields are unsigned bytes. The new format lookup first excludes NVN attributes outside the actual 16-entry bound-format array. Reflected locations only form the numeric declaration pattern and recipe key. The helper accepts the translator's existing scalar/vector float, uint and int declaration shape; an unsupported declaration shape refuses when retyping is required.

Canopy's existing seed verifier requires hashed MSL for every counted variant, paired reflection and consistent indexed dependencies; a standalone metallib cannot satisfy that contract. Runtime loading records the source path when it successfully reads MSL even when using a precompiled Metal library. The readable-source refusal remains necessary for older standalone inputs and later read failure. These facts do not grant imported metadata native translation or execution authority.
