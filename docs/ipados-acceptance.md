# Next physical iPad acceptance run

Target: TOTK 1.4.3 on the existing M4 iPad. Cloud changes are recorded in [the audit](ipados-cloud-audit.md). Do not treat a successful build, install, drawable resize, HUD counter, or locked-device test block as functional acceptance.

The [full-roadmap continuation](ipados-roadmap-status.md) prohibits executing tests or simulators. This is an ordered checklist for a later authorized local validation session, not permission to execute it now. Include the new [Controls source](ipados-controls.md), which has been reviewed but not built or tested.

1. **Prepare privately.** Unlock the iPad, confirm device ownership, retain the previous signed app for rollback, and back up the current complete save/profile and account identity. Record the exact candidate commit and build options. Reuse local inputs, signing configuration and Xcode caches; preserve bundle identity/team. Build the candidate and run the full macOS tests, including all 16 Foundation save/preferences tests, before installation. No simulator is needed.
2. **Install and verify preservation.** Compare every save/profile file with its immediate pre-install private SHA256 snapshot. Record installation separately from launch/gameplay. Stop and investigate any unexplained save or identity change before Play.
3. **Launcher, before Play.** Check the centered landscape card, scrollable rows, touch/accessibility labels and connected-controller navigation. Change implemented preferences, relaunch, and check persistence, malformed-value recovery, language/System behavior and foreground return. Confirm unsupported display controls stay disabled. Test both Automatic touch and controller-required Off. Restore the intended settings before Play.
4. **Saves, before Play.** Export through Files and compare all bytes privately; import that verified folder, then restore a known own backup. After each replacement compare the active save and account identity with the corresponding immediate snapshot. Check backup creation and staging cleanup. Try canceled/unavailable cloud-provider access and incomplete input; require a useful error and unchanged active save/identity. A synthetic read-denial probe does not replace an actual provider test. Keep the original export intact.
5. **Play and live input.** Press Play once, load the known existing save, and avoid New Game or overwrite prompts. Open/close gear and Escape menus while holding touch buttons/sticks and mouse buttons; require no stuck input, camera motion or input leakage. Test background/foreground, scene/key-window focus loss, pointer-lock denial/loss, mouse/controller disconnect and reconnect. Mouse input resumes only after focus and actual pointer lock return. The menu does not pause gameplay; controller input may still reach the game. Confirm save transfers remain inaccessible after Play. Check Full/FPS/Off and native HUD persistence; native HUD may require the device Developer setting.
6. **Projection and UI.** Compare default 720-high 16:9 with experimental Full display and 1080 high in separate app launches. At 4:3 the full canvas requests 960×720 or 1440×1080. Confirm actual scene render targets with GPU capture and drawable size separately. Check camera proportions/FOV, HUD, world markers, map, menus, cutscenes, effects and touch layout. Keys 3/4 must not change the iPad canvas/projection. Known marker/pixel-snapped UI limitations keep Full display experimental.
7. **Performance, separately.** Select and warm three real scenes, agree numerical stability thresholds, and follow the [30-minute baseline protocol](ipados-baseline.md). Distinguish native rendered, interpolated and presented frames; capture synchronized frame times, memory and thermal state. Use the [graphics inventory and trace analyzer](ipados-graphics.md) for supporting evidence. Partial TSV readback and present-call cadence cannot establish stable native 60 FPS.

Keep raw captures, saves, account/device identifiers and signing material private. Record pass/fail/unavailable for each step with the actual tested commit. A blocked test has no functional result. Leave hardware-dependent issue acceptance open until the corresponding evidence exists.
